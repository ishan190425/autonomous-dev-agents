### Introduction

For the past two months, we've been running an experiment: What if an AI team could develop software autonomously, 24/7, without human intervention?

Not AI-assisted coding. Not copilots. Actual autonomous development — where AI agents pick tasks, write code, review PRs, and ship features independently.

The result? **1,200+ dispatch cycles**, **116 merged PRs**, and **2,800+ passing tests** — all generated by AI agents working as a coordinated team.

Here's how we built it.

### The Problem with AI Copilots

Don't get me wrong — Copilot, Cursor, and Claude are incredible tools. I use them daily.

But they have a fundamental limitation: **they require you**.

Every suggestion needs a human to accept. Every code block needs a human to review. Every feature needs a human to initiate.

What if you could go further? What if AI agents could:

- Check your issue backlog
- Pick the highest-priority task
- Research the solution
- Write the code with tests
- Open a PR
- Get it merged

All while you sleep?

### Introducing ADA: Autonomous Dev Agents

ADA (Autonomous Dev Agents) is our answer. It's an open-source framework for running autonomous AI development teams on any repository.

**Core concept:** Multiple specialized AI agents take turns acting on your codebase. Each agent has a role (Engineering, QA, Product, etc.) and a playbook defining what actions they can take.

A "dispatch cycle" works like this:

```
1. Check rotation → Which agent's turn?
2. Read memory → What's the context?
3. Check GitHub → What needs work?
4. Pick action → What should I do?
5. Execute → Write code, create PR, etc.
6. Update memory → Pass context to next agent
7. Complete → Next agent's turn
```

This runs continuously. 24/7. Indefinitely.

### The 10-Agent Team

Our production ADA team has 10 specialized roles:

| Role           | Responsibility                      |
| -------------- | ----------------------------------- |
| 👔 CEO         | Strategic decisions, priorities     |
| 🚀 Growth      | Marketing, community, content       |
| 🔬 Research    | Technical analysis, benchmarks      |
| 🌌 Frontier    | Architecture, system design         |
| 📦 Product     | Feature specs, acceptance criteria  |
| 📋 Scrum       | Retrospectives, process improvement |
| 🔍 QA          | Testing, quality assurance          |
| ⚙️ Engineering | Code implementation                 |
| 🛡️ Ops         | CI/CD, infrastructure, rules        |
| 🎨 Design      | UX specs, developer experience      |

Each role has a playbook — a markdown file defining:

- What actions they can take
- When to take them
- How to format their output
- Dependencies on other roles

The rotation ensures every role gets regular turns, preventing any single aspect (like just writing code without tests) from dominating.

### The Memory Bank: How AI Agents Remember

The biggest challenge with autonomous AI: **context loss**.

LLM agents start fresh each invocation. They don't remember previous sessions. Without intervention, your Engineering agent wouldn't know what QA found yesterday.

Our solution: **the memory bank**.

```markdown
# 🧠 Memory Bank

## Current Status

- Sprint 3 in progress
- v1.0.0-alpha live on npm
- Focus: billing integration

## Active Threads

- **#155** (P0) — SaaS Container launch
- **#183** (P1) — Interactive onboarding

## Role State

### Engineering

- Last: Implemented conversion module
- Next: Stripe integration
  ...
```

Every agent:

1. **Reads** the memory bank before acting
2. **Updates** their section after acting
3. **Never deletes** other agents' sections

It's a simple pattern that creates powerful continuity. Agent A's insights persist for Agent B, even though they're separate invocations.

### Dogfooding: Building ADA with ADA

Here's where it gets meta: **ADA builds itself**.

Our `autonomous-dev-agents` repo is developed by its own agent team. The agents have:

- Written 17 operational rules
- Captured 763 lessons learned
- Created and refined 10 role playbooks
- Built the CLI tool that runs them

When we found a bug in the dispatch system, an agent created the GitHub issue, another researched the fix, Engineering implemented it, QA wrote tests, and Ops merged the PR.

All autonomous. We just watched the commits roll in.

### How to Get Started

ADA is open source and available today:

```bash
# Install globally
npm install -g @ada-ai/cli

# Initialize in your repo
ada init

# Run a dispatch cycle
ada dispatch start
# ... agent does work ...
ada dispatch complete --action "What was done"
```

The `ada init` command scaffolds:

- `agents/` directory structure
- Default role playbooks
- Memory bank template
- Rotation configuration

You can start with a single agent and scale up as you're comfortable.
