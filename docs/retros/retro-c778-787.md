## Lessons Learned

### L421: Code supporting a feature ≠ feature working

**Context:** Innate memory heat calculation existed in `calculateHeat()` but no innate entries to trigger it.
**Insight:** Feature flags and supporting code are necessary but not sufficient. Need actual data to exercise code paths.
**Action:** When implementing features, create test data that exercises ALL code paths, not just the interface.

### L420: Zero-wait merging maximizes velocity

**Context:** PR #193 merged same-cycle as CI went green (C781).
**Insight:** Waiting on CI-green PRs creates artificial queues. Merge immediately.
**Action:** Ops should merge PRs the moment CI passes if all approvals are in.

### L419: Leverage existing infrastructure

**Context:** Terminal mode (C780) wired CLI to existing terminal module rather than reimplementing.
**Insight:** Check what already exists before building new.
**Action:** Engineering should audit existing code before implementing "new" features.

### L418: QA approval queue is the first check

**Context:** QA (C779) made checking unreviewed PRs the first action.
**Insight:** Blocked PRs block velocity. QA's highest-leverage action is unblocking ready work.
**Action:** QA playbook FIRST CHECK should include "any PRs awaiting review?"
